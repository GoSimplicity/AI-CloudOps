# 通知错误与部分结果

本模块、机器人 token 交换和通知 HTTP helper 的错误/日志只使用固定操作分类、数字 HTTP 状态或 provider code，不记录 token、AppSecret、用户/群机器人 URL、query、请求/响应正文或 provider message。已配置的 HTTP 方法、上下文、客户端超时、2xx 判断与发送内容保持；没有新增自动重试。

群聊与私聊的正常 provider 成功 envelope 为 `code: 0`，只接受单个 JSON 对象中唯一、显式、整数的 `code`；不接受无项目合同证据的 `StatusCode` 替代。非零业务码、格式错误或缺少结果码均作为未确认处理。失败响应正文不会从 HTTP helper 返回给调用方。有效 Code0 的 token 响应仍必须有非空白 token 和正且可表示的过期秒数，才会进入缓存。没有凭据时继续静默跳过轮询；有效凭据的私有 token 刷新和租户 token 并发缓存仍沿用原流程。

私聊尝试所有收件人：单个 transport、HTTP 或业务失败不会跳过后续收件人，结束后返回固定部分失败错误。收件人集合为空时在读取 token 之前直接无操作；缓存 token 为空时不发无效请求。群 token 未配置时，直接调用群发送函数会零 HTTP 返回未配置错误，编排函数则跳过该未配置通道。

通知编排保持先私聊、后群聊的正常顺序；私聊失败仍尝试已配置群通道，最后聚合结果。部分收件人或另一通道可能已经成功，返回失败不代表所有副作用都未发生；应人工核对，不应盲目重试。此实现没有分布式事务或 exactly-once 保证。

额外的纯日志收敛涵盖文本群发送 DAO 的成功/失败日志，以及 `/receive` 的 JSON 读取错误，未改变其业务处理或队列。文本群发送 DAO 与机器人 token 交换也在 HTTP 成功后共用同一显式业务确认器；unknown 额外字段允许存在，但缺失/null/错误类型、重复 code、额外 JSON 值均拒绝。本说明不声称仓库所有 DAO/通知代码都已统一。
