# 告警规则发布合同

告警规则按采集池读取一次活动规则，并复制池目标、规则、Labels 和 Annotations。版本指纹与生成文件消费同一份快照，包含规则名称、表达式、持续时间、标签、注解及目标顺序，避免字段更新后仍命中旧缓存。保存和 YAML 构造合同见 [alert-rule-construction.md](alert-rule-construction.md)。

活动规则确实为空时，每个目标得到 `groups: []`，用于清除此前规则。读取失败、全部历史条目无效或构造失败保留上一份有效发布；部分无效历史条目仍按构造合同逐条隔离。

清空目标与清空规则分别处理：API 允许将采集池实例保存为 `[]`，该明确的空目标集合应退役本池此前管理的配置、缓存及成员；它不为任何目标写入规则文件。规则读取失败仍不能被当作清空授权。

## 发布与恢复

完成键采用独立 `publication:alert_rule:pool:<ID>` 命名空间，以稳定的采集池 ID 定位。旧的名称哈希键不再作为完成依据，也不自动删除或迁移。首次升级会重新发布。

在任何成员、数据库或配置缓存写入前，先持久写入 `pending:<目标哈希>`。随后登记目标成员、更新配置元数据、写入各目标内容并清理已移除目标，全部成功才确认正式 SHA。写入失败保留 pending，下一次调用重新修复；源从 A 改为 B 后发布中断，再回到 A，也不能借旧 A 完成键跳过恢复。缓存实例重建和池更名不绕过恢复。

写入前分页检查告警类型的配置元数据，只有池 ID、配置类型、规范生成名称和实例地址均匹配的行才归本发布器管理。目标或待清理地址存在自定义、其他池或重复元数据时拒绝发布，避免覆盖或删除其他配置。声明总数与实际扫描不符、提前空页、跨页总数变化、重复行 ID 等可观测异常也在写入前拒绝；COUNT/OFFSET 分页并不因此成为事务一致快照。清理不使用通配符；成员在对应清理步骤完成后移除，以便失败重试。

同一个缓存实例的发布调用串行执行，并检查上下文取消。Redis 和数据库之间没有分布式事务：失败时可能已有部分有效配置可见，pending 表示尚未完成，不能解释为跨进程原子性或 exactly-once。

首次采用稳定规则 group 身份的 Prometheus 状态边界仍见构造合同；本阶段没有连接或重载真实 Prometheus。

## 验证范围

新增 14 个发布主测试及 81 个子场景通过，覆盖字段单独更新、单次读取快照、真空规则、空目标退役、读取/无效历史保留、发布各阶段故障、A/B 回退、池更名和缓存实例重建、旧名称键碰撞、成员登记、跨页元数据归属冲突、无成员索引的旧孤儿、不完整分页拒绝、取消与同实例串行。

冻结代码后，全仓 `go test ./...`、`go vet ./...` 通过；cache、utils、alert service 完整三包 race 通过。`integration,smoke,schema_smoke` 标签仅执行编译检查，不能作为真实数据库或浏览器集成验收。发布专项使用内存替身，不调用真实 Prometheus、云平台、通知或生产服务。
