# Cron 重试预算修复

## 行为与兼容边界

`max_retry` 现在直接作为 Asynq 的 `MaxRetry(N)` 传给手动入队和定时注册，表示首次执行之外允许的队列重试次数，范围为 0～10。此前两条路径没有传入配置，会落入 SDK 默认的 25 次重试。

创建时省略字段默认 3，显式 0 保留为 0。更新时省略字段保留数据库原值，显式 0 关闭自动重试。数据库列继续保留原来的默认值 3，不需要迁移；DAO 在创建事务中显式写回 0，避免 GORM 的整型零值默认值行为将它改成 3。

重试预算同时约束任务业务失败和 Asynq 的硬崩溃恢复。显式 0 也关闭硬崩溃后的自动重投；最后一次允许的尝试崩溃后，SDK 无剩余预算，不保证再次恢复。默认 3 为普通失败或单次进程崩溃提供恢复空间，不承诺无限恢复。外部命令仍应设计为幂等操作，不能依赖队列提供 exactly-once。

租约占用和已丢失归属属于协调等待，通过 Asynq `IsFailure` 返回 false，保持重投但不计入失败预算；真正的执行错误与 SDK 执行期限失效继续按原生预算计数。重试预算变化会刷新定时注册，仅影响之后的入队；已排队任务保留其入队时的选项。

配置更新改为仅写入配置字段，避免旧的 `Save` 把正在执行的租约、启用状态、历史输出和创建者覆盖为请求模型中的零值。


- 手动与定时入口捕获真实 Asynq 选项，验证 0、3、10 均精确传递，变更后刷新注册
- 真实 SQLite 覆盖 0 的持久化、运行中配置编辑及租约保持
