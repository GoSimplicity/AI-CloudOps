# 本地主机元数据与凭据合同

`tags` 的读取和写入格式均为 `{key, value}[]`，与 KeyValueList 持久化结构一致。前端接受 `team=ops` 或无值标签 `team`，按键去重

更新接口只写本次提供的字段；省略保留，描述、环境和标签可显式清空。用户名修改会持久化，不重置运行状态或覆盖采集字段。空或省略的 password/key 表示保留现有凭据，仅非空值触发轮换；页面编辑同一认证方式时可留空，切换认证方式时要求提供相应凭据

本地主机列表、详情与服务树关联对象 JSON 不返回私钥。SSH 与定时任务仍从内部 DAO/连接服务取得凭据，不依赖 API 响应中的 key 字段。私钥既有数据库存储格式未在此阶段迁移；备份和数据库仍应按敏感凭据存储保护

元数据更新使用明确字段集合，不回写读取时的旧凭据快照，因此不覆盖并发轮换的值。前端提交在异步校验开始前锁定，取消后重开的表单不受旧请求完成影响；取消界面不撤销已经送达服务端的写操作

验证：旧实现真实 SQLite 测试复现描述/标签清空与用户名修改丢失；修复后 service/dao/model/cron executor race 通过，全仓构建通过。前端真实 Antd 组件覆盖对象标签、保留密钥、同键去重、重复提交与取消重开；隔离 MySQL/浏览器结果在联合验收后补记
