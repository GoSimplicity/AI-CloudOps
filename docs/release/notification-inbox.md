# 工单站内消息

`in_app` 通知由工单事件投递，支持创建人、处理人、系统用户、角色及部门；不接受外部地址作为站内收件人。每次事件至多展开 1000 个用户，消息与成功投递账本在租约保护下同事务写入，同事件、通知配置和用户只保存一条。延迟、定时、取消与重试沿用事件状态机；已投递消息的删除保留去重墓碑并清除正文，重试不会恢复已删除内容。

收件箱提供列表、未读数、单条已读、全部已读和单条删除；每次查询和写入按可信登录用户过滤。五个 API 分别登记为权限，普通角色需要显式授予所需方法和路径，超级管理员遵循现有全局规则。外部地址的 `test/send` 不支持站内消息。工单普通评论与评论事件同事务保存，系统评论只允许可信内部调用设置。

升级前停止旧通知 worker，备份并完成新表迁移，再启动新版本；不要将不识别 `in_app` 的旧 worker 与新版本混跑。消息删除后保留去重墓碑，目前没有自动保留期限或清理策略，需在制定审计和保留政策后实现安全清理。隔离 MySQL 并发、事务失败、延迟取消及跨用户测试已执行；未向任何外部接收人发送消息，也未操作生产环境。
