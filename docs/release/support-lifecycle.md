# 告警与录制规则支持开关生命周期

告警规则和录制规则生成器先读取完整、未按支持状态过滤的采集池库存。只有所有页通过总数、唯一正ID、完整性及上下文检查，才开始处理任何池；读取每页时即复制状态、目标和标签，避免后续页复用对象改变已读取输入。Prometheus主配置复用同一个库存读取器，渲染及发布逻辑保持。

各生成器只解释自己的开关：`1`正常生成，明确的`2`按空目标集合退役本模块生成物；`0`及其它未知值保留原生成物并报错。关闭录制规则不会关闭告警规则，也不修改Prometheus主配置。未出现于库存的池不作为关闭依据，池删除和全局调度开关不属于本阶段。

明确关闭时不读取或验证已禁用的规则源，因此坏历史规则或规则DAO错误不会阻止关闭。当前池目标也不参与生成缓存键，包括无效或不可信地址；清退只使用成员索引和元数据中可验证归属的旧生成物。正常开启时继续遵守原有读取、构造失败保留最后有效版本的合同。

元数据必须同时满足正确PoolID、配置类型、规范名称和有效实例地址。只有名称符合规范但PoolID不同，仍属于冲突，不能据名字猜测归属。自定义、他池、重复或不完整元数据在任何写入前拒绝；没有成员索引但元数据归属明确的旧生成物可被发现和退役。

版本指纹包含相关开关，开启但空目标与明确关闭仍是不同版本。完成键沿用独立PoolID命名空间，升级后会重新确认发布状态；pending先于成员或配置写入，全部元数据、Redis及清理完成后才确认SHA。失败后可继续关闭或恢复开启，更名和重建缓存实例不能绕过恢复。

这仍是可重试收敛流程，无法将Redis与数据库写入变成跨系统或跨进程事务；分页计数检查也不是SQL一致快照。设置保存、发布SHA和真实Prometheus应用确认是不同层次，本阶段未执行真实实例重载或验证实际告警停止。

未知历史Redis-only孤键既没有元数据也没有成员归属，本阶段不猜删。仓内旧`ConfigYamlService`没有DI或HTTP消费者，当前注册的配置接口读取数据库；不能把未知Redis垃圾说成已清退，也不把它推断为真实告警仍执行。

## 验证

新增9个主测试、80个子场景及完整旧缓存测试通过，覆盖开关循环、单类隔离、坏源关闭、未知状态、开关版本、故障回退、更名重建、pending失败、当前/退役归属冲突、库存后页失败与对象复用。旧实现的可编译运行红例证明关闭后仍遗留成员等缺口，修复后通过。

独立4个最小内存场景通过race：关闭不读两类规则DAO、不触另一类或主配置、不从坏目标构造Redis键，以及规范名称但错误PoolID的孤立冲突零写拒绝。最终全Go test/vet、cache/utils/alert service完整race、全标签只编译通过。全部本地或隔离测试，没有上线或生产连接。
