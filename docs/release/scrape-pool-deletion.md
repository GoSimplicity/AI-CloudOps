# 采集池删除与关联定义保护

## D1：完整定义引用检查

删除采集池不再仅依赖服务层的启用job预检。最终DAO事务锁定未删除父池，检查全部未删除的采集任务、告警规则和录制规则，包含禁用定义；任何引用或查询错误都阻止软删除。没有自动删除用户定义，也不把同号AlertManager池当作Scrape池。

三类定义创建或迁移时，在自己的写事务内锁定并验证目标父池仍存在且未删除，再锁定或写入子行。删除与关联写使用同一父行锁协议，避免服务层先查后写留下并发孤儿。record更新省略PoolID时保留原有struct更新语义，并在锁内重检初读的关联没有被另一请求迁移。

本阶段没有添加数据库外键或改变schema，也不约束绕过DAO的手工SQL。服务层原启用job友好提示保留，权威检查在DAO；检查和删除失败均保留原数据。

## 验证

新增7个主测试、27个子场景及原有目标包测试通过，覆盖三类启用/禁用引用、缺失或已删父池、迁移和省略关联、查询错误回滚及真实删除handler拒绝。旧实现对照保持可编译并出现明确业务断言失败，无nil依赖panic充当红例。

独立4个内存race场景验证省略关联的竞争迁移检测和三类父查询后的取消传播；SQLite仅证明事务连接及锁子句，不能冒充MySQL行锁。

另在专属本机MySQL临时库实际执行6个锁先后场景：job、alert、record各自的创建先行与删除先行，全部通过且零skip。没有触碰演示数据，临时库、专属账号和DSN随后清理。最终全Go test/vet、相关包完整race、全标签只编译通过。

## D2：真实删除记录驱动生成物退役

真实数据库软删除记录现在是持久清退授权。普通列表继续只显示未删除池；控制器另完整读取包含tombstone的生命周期库存，检查所有页、唯一ID和复制快照后才发布。普通缺失、错误或伪造的删除状态不授权清理。

服务删除完成父池事务后，同步等待主配置、告警规则、录制规则三类退役，只有全部成功才返回完成。部分失败明确返回待重试；同ID重复DELETE重新验证真实tombstone。周期管理器的独立退休任务可在重建后恢复，正常告警/录制生成暂停不会遗失已接受的删除意图；没有启用被暂停的正常生成。

三个发布器先取得原实例mutex，等待旧快照发布结束，再重新确认tombstone，使用独立删除版本、pending及原归属CAS清空desired。删除分支不读取坏的旧job/rule源，不自动删除历史用户定义。AM同号的type2/5、自定义及foreign行不属于清退范围。

已证明归属的所有旧目标（包括只有DB、没有成员索引的历史行）在pending之后、任何SQL退役之前先可靠登记成员。DB已软删而Redis删除失败，仍可由tombstone和成员重建恢复；该锚点也补到正常关闭、清空及迁移目标的共同清退路径。成员最后移除，未知无DB/索引的Redis-only孤键不猜删。

新增D2累计83叶场景覆盖三类同步/周期/失败重建、完整库存、inflight协调、HTTP列表与详情不再提供已退役配置，以及live路径的16个无索引恢复回归。独立真实SQLite DAO+HTTP反例验证部分退役后取消返回失败且保tombstone，重建后正常生成关闭仍恢复三类。HTTP测试使用持久临时文件SQLite，避免取消导致连接丢弃时`:memory:`夹具自身消失；原三场景连续50次race通过，原断言未削弱。

最终全Go test/vet、相关七包完整race、全标签只编译通过。本阶段不修改CAS核心或AM，不保证跨系统事务、跨进程exactly-once或真实实例已应用，也没有上线。
