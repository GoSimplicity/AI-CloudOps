# 1.0 通知触发边界

工单自动通知当前只实现即时事件触发。原来的delayed/scheduled/conditional虽然可以存储，却没有对应执行引擎；按即时方式发送会提前投递。因此1.0不开放这些未实现能力

创建只接受trigger_type=immediate；更新显式指定其他类型会拒绝。提供ScheduledTime、RepeatInterval或非空TriggerCondition同样拒绝，不以保存成功冒充调度生效。历史非即时配置可读取、修改普通元数据和禁用；不能直接启用，必须由操作者明确转为即时类型。历史字段保留在数据库，自动事件处理在收件人查询和通道发送之前拒绝非即时配置，不静默提前发送

手动测试发送仍是操作者明确选择配置、通道与地址后的一次独立动作，不代表高级触发已实现。即时通知的邮件/飞书应用通道、部门/custom接收人与逐通道去重继续有效；AIOps飞书自定义机器人使用独立服务端webhook配置，不与工单应用ID收件人混用

验证：四种非即时/未知类型的创建、更新和历史自动发送先红复现，定时/重复/条件参数误接受、历史配置重新启用也先红；修复后workorder全模块race通过。既有真实本机HTTP飞书应用替身收件箱以明确immediate配置继续验证部门/custom去重、禁用用户排除与上游失败传播，不发送到外部

后续来源与激活回归补齐：历史 `immediate` 若仍携带任一高级参数也禁止自动发送和重新启用；现有 DTO 无法清除定时/重复指针时应新建即时配置，不能仅改类型绕过。见 [notification-scope.md](notification-scope.md)。
