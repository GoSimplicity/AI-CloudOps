# 非计算云资源合同

首批引入阿里云 RDS、传统 CLB 和 Tair/Redis/Memcache 的独立只读 DTO 与指定 ID 查询，字段不混用 ECS 的 SSH 或计算实例数据。每次提供 1 至 100 个 ID，逐项校验地域、ID、数量和分页；缺失、重复、超出范围或上游错误均整体失败。没有查询权限覆盖证明时不做全量删除。最低权限分别为 `rds:DescribeDBInstances`、`slb:DescribeLoadBalancers` 和 `kvstore:DescribeInstances`。

本阶段只有 SDK 合同及本地假传输测试，没有 API、数据库对账、前端入口或真实云验收；ALB/NLB 与其他云厂商也尚未接入。旧版 SDK 单次读取的超时上限为 30 秒，取消可能不会立即生效。后续增量同步必须使用独立资源表与地域租约，并保留本地维护字段。

## 增量对账与历史

阿里云账户可按已授权地域、资源类型和明确 ID 集合增量读取并写入独立资源表；地域租约、账户凭据版本和状态在短事务中重新验证。同步只更新云元数据，不覆盖本地描述，也不删除缺席资源。操作历史按账户、地域和类型隔离，记录操作者、资源 ID、结果及计数；提交结果或审计不可用时返回 `unknown`/`audit_unavailable` 且 `retry_safe=false`，应先核对，不能盲目重试。列表、详情、同步和历史各自使用现有 JWT 与方法级 RBAC，账户范围受全局 API 权限约束，当前没有额外租户 ACL。

升级前必须停止所有旧版 API 和 worker，备份并完成两个新表迁移后统一启动；旧版本不检查托管资源关联，混跑可能删除其账户或地域。现有账户/地域单删、批删和替换均在一致锁序下检查计算与托管资源。独立 MySQL 假云测试验证了提交、回滚、租约 fencing 和删除竞争；未连接真实云。

## 已有历史的人工核对

`POST /api/tree/cloud/managed/history/:id/resolve` 要求独立精确方法和路径授权，通配符不隐式放行。请求需包含原账户、地域、类型、`resources_verified=true` 和10至1000字理由；操作人取可信JWT。核对只记录审计时间、用户和理由，不改变原始同步结果、不调用云API、不重新同步。核对允许账户或地域保持停用，服务取得新地域租约并在事务中校验当前配置；正常同步仍要求启用状态；正在同步时拒绝核对，旧worker被fence且不能覆盖核对记录。

服务端在新的同步前拒绝该范围中未核对的 unknown/running 历史，不能绕过页面直接重试。已有成功历史也允许人工确认，以处理HTTP响应丢失；同一历史不允许覆盖已有核对理由。history 返回 resolved_at/resolved_by/resolution_reason 及 retry_safe，原状态仍保留。

本阶段完成后端和SQLite竞态/权限及隔离MySQL回归；界面接线仍待完成。没有历史记录的 audit_unavailable 不能调用按历史ID核对接口，独立范围级处置仍需继续开发；不能把清除浏览器标记当作解除审计阻断。

## 持久操作 ID

新调用方可在同步请求中提供规范小写 UUID `operation_id`，同一用户、同一 ID 绑定账户、地域、类型和排序后的资源 ID 摘要。数据库唯一记录与独立随机领取令牌共同决定首次执行资格，不依赖 MySQL `clientFoundRows` 下变化的行数。重复提交只返回已保存结果；运行中、崩溃或结果未确认的操作禁止再次执行。失败结果也不会以同 ID 自动重跑，需要核对后明确创建新操作。

`GET /api/tree/cloud/managed/operations/:operation_id` 独立授权，仅返回当前 JWT 用户的状态、范围及有界结果，不公开领取令牌或请求摘要。数据库确认失败时返回 unknown/operation_audit_unavailable，不把资源提交成功误报成完整操作交付成功。超过两分钟的运行中记录在查询时显示 unknown，但不会自动删除或再次执行。

新增操作表由启动迁移注册。原已发布的无ID请求保留兼容合同，不具有跨响应丢失的请求防重保证；前端稳定ID接线和缺失记录的核对墓碑仍在后续阶段。记录是持久防重依据，目前不自动清理，必须先制定可审计保留策略并隔绝所有旧请求后才能回收。数据库持久性依赖实际 MySQL 配置，异步故障切换/恢复旧备份不能视作已验证的零丢失。

SQLite竞态、重启/用户隔离、持久化回执失败、损坏结果及隔离MySQL clientFoundRows验证通过；未连接真实云。

## 操作记录缺失时的核对墓碑

`POST /api/tree/cloud/managed/operations/:operation_id/resolve` 使用独立精确授权，按当前JWT用户隔离。请求需提供原账户、地域、类型、资源ID、`resources_verified=true` 和10至1000字理由。人工确认后只写审计，不执行同步；若操作记录不存在，会在同一受地域租约保护的事务中创建 reviewed 墓碑，previous_state=not_recorded，明确其资源ID来自人工核对而非虚构的原成功记录。迟到请求使用相同ID时无法再取得执行资格。

已有记录必须匹配原请求摘要，原结果保留，重复核对不能覆盖已有理由；关联同一用户及operation_id的历史一并记录核对信息。操作查询返回 reviewed_at/reviewed_by/review_reason/previous_state 和有界资源ID。旧版本记录若缺资源ID快照，只有请求摘要匹配后才补入核对快照。

正常同步在云查询前和资源提交事务内验证操作领取状态，防止已领取但尚未取地域租约的旧请求在核对后继续提交。核对与资源提交采用一致账户→地域→租约→操作锁序。停用账户/地域可核对且不会重新启用；已删除范围不在本接口支持范围内。新旧无ID客户端不能混用后声称有请求级防重，旧 pending 浏览器标记不能凭空关联到新操作ID。

本阶段完成后端，前端稳定operation_id及按操作核对入口仍待接线。SQLite竞态、精确权限、缺失墓碑、迟到请求、停用范围和隔离MySQL测试通过，未访问真实云。
