# 非计算云资源合同

首批引入阿里云 RDS、传统 CLB 和 Tair/Redis/Memcache 的独立只读 DTO 与指定 ID 查询，字段不混用 ECS 的 SSH 或计算实例数据。每次提供 1 至 100 个 ID，逐项校验地域、ID、数量和分页；缺失、重复、超出范围或上游错误均整体失败。没有查询权限覆盖证明时不做全量删除。最低权限分别为 `rds:DescribeDBInstances`、`slb:DescribeLoadBalancers` 和 `kvstore:DescribeInstances`。

本阶段只有 SDK 合同及本地假传输测试，没有 API、数据库对账、前端入口或真实云验收；ALB/NLB 与其他云厂商也尚未接入。旧版 SDK 单次读取的超时上限为 30 秒，取消可能不会立即生效。后续增量同步必须使用独立资源表与地域租约，并保留本地维护字段。

## 增量对账与历史

阿里云账户可按已授权地域、资源类型和明确 ID 集合增量读取并写入独立资源表；地域租约、账户凭据版本和状态在短事务中重新验证。同步只更新云元数据，不覆盖本地描述，也不删除缺席资源。操作历史按账户、地域和类型隔离，记录操作者、资源 ID、结果及计数；提交结果或审计不可用时返回 `unknown`/`audit_unavailable` 且 `retry_safe=false`，应先核对，不能盲目重试。列表、详情、同步和历史各自使用现有 JWT 与方法级 RBAC，账户范围受全局 API 权限约束，当前没有额外租户 ACL。

升级前必须停止所有旧版 API 和 worker，备份并完成两个新表迁移后统一启动；旧版本不检查托管资源关联，混跑可能删除其账户或地域。现有账户/地域单删、批删和替换均在一致锁序下检查计算与托管资源。独立 MySQL 假云测试验证了提交、回滚、租约 fencing 和删除竞争；未连接真实云。

## 已有历史的人工核对

`POST /api/tree/cloud/managed/history/:id/resolve` 要求独立精确方法和路径授权，通配符不隐式放行。请求需包含原账户、地域、类型、`resources_verified=true` 和10至1000字理由；操作人取可信JWT。核对只记录审计时间、用户和理由，不改变原始同步结果、不调用云API、不重新同步。账号/地域需保持启用，服务取得新地域租约并在事务中校验当前配置；正在同步时拒绝核对，旧worker被fence且不能覆盖核对记录。

服务端在新的同步前拒绝该范围中未核对的 unknown/running 历史，不能绕过页面直接重试。已有成功历史也允许人工确认，以处理HTTP响应丢失；同一历史不允许覆盖已有核对理由。history 返回 resolved_at/resolved_by/resolution_reason 及 retry_safe，原状态仍保留。

本阶段完成后端和SQLite竞态/权限及隔离MySQL回归；界面接线仍待完成。没有历史记录的 audit_unavailable 不能调用按历史ID核对接口，独立范围级处置仍需继续开发；不能把清除浏览器标记当作解除审计阻断。
